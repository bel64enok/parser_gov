# Tender Radar

Прототип web-системы для парсинга, тегирования и первичного анализа тендеров с `zakupki.gov.ru`.

## Что реализовано

- загрузка закупок через официальный HTML-поиск ЕИС с устойчивым fallback, если портал недоступен;
- карточки тендеров с ранжированием, доменами, продуктовой маркировкой и тегами;
- отбор списка по автоматически проставленным и пользовательским тегам;
- критерии анализа MVP по примеру из документа: домен, способ закупки, сроки подачи заявок;
- загрузка документации `zip`, `docx`, `xlsx`, `pdf`, `txt`, `csv`;
- извлечение текста из DOCX/XLSX и текстового слоя PDF;
- web-интерфейс в стилистике Beeline Yellow: желтый акцент, черно-белая рабочая палитра, плотная B2B-компоновка;
- API без внешних web-зависимостей, чтобы прототип запускался из папки проекта.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

После запуска откройте:

```text
http://127.0.0.1:8000
```

## API

- `GET /api/tenders?limit=50` - загрузка и анализ закупок.
- `POST /api/upload` - загрузка файла документации в поле `file`.
- `GET /api/requirements` - требования, извлеченные из исходных документов.
- `GET /api/health` - проверка сервера.

## Ограничения прототипа

- ЕИС может отвечать медленно или блокировать частые запросы; в этом случае UI явно показывает fallback-режим.
- OCR для PDF без текстового слоя пока не включен, отмечен как следующий этап.
- RAR-архивы требуют отдельного распаковщика; ZIP поддержан встроенно.
- Производственный контур должен вынести критерии анализа и словари в БД/админку, добавить аудит и фоновые очереди.
