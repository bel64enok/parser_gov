# Tender Radar

Прототип системы для скачивания, ИИ-анализа и показа тендеров с `zakupki.gov.ru`.

## Архитектура: 3 стадии вокруг локального хранилища

```
        cron (раз в час)
              │
   ┌──────────▼───────────┐
   │  pipeline.py          │
   │  1) fetcher.fetch_new │──► zakupki.gov.ru (листинг + карточка + вложения)
   │  2) analyzer.analyze  │──► RMR gateway (ИИ поверх правил)
   └──────────┬───────────┘
              │ пишет
   ┌──────────▼───────────┐        ┌────────────────────┐
   │ data/tenders.db       │◄───────│ app.py (HTTP)       │◄── браузер
   │ data/tenders/<номер>/ │ читает │ /api/tenders+фильтры│
   └───────────────────────┘        └────────────────────┘
```

Стадии разнесены и идемпотентны: `fetched` → `analyzed` (или `error`).

| Модуль | Роль |
|---|---|
| `db.py` | SQLite-хранилище: тендеры, документы, анализ; `query_tenders(filters)` |
| `scrape.py` | скрейпинг листинга ЕИС + скачивание вложений (`fetch_attachments`) |
| `extract.py` | извлечение текста: docx / xlsx / pdf-text-layer / txt / csv / zip / html |
| `rules.py` | детерминированный анализ: домены, скоринг, чеклист, evidence |
| `ai.py` | клиент RMR-шлюза (OpenAI-совместимый), `ai_enrich()` поверх правил |
| `fetcher.py` | стадия 1 — скачивание |
| `analyzer.py` | стадия 2 — извлечение текста + правила + ИИ |
| `pipeline.py` | cron-вход: стадия 1 → стадия 2 |
| `app.py` | стадия 3 — backend, читает из БД, фильтры по датам |

Документы в карточке — реальные файлы, скачанные пайплайном, со ссылками на источник ЕИС и подсветкой доказательных фрагментов по критериям анализа.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 1) наполнить хранилище (скачать + проанализировать)
python pipeline.py "мобильная связь" 10

# 2) поднять веб-интерфейс (читает из data/tenders.db)
python app.py            # http://127.0.0.1:8000
PORT=9000 python app.py  # другой порт
```

## ИИ-шлюз (стадия 2)

Анализ ИИ опционален и **дополняет** правила. Без ключей пайплайн работает на одних правилах.
Конфиг через переменные окружения:

```bash
export RMR_GATEWAY_URL="https://api.neuraldeep.ru/v1"   # base_url (OpenAI-совместимый)
export RMR_API_KEY="sk-..."                             # секрет, не коммитить
export RMR_MODEL="gpt-oss-120b"
```

Проверено на `api.neuraldeep.ru/v1` с моделью `gpt-oss-120b`: возвращает валидный JSON
(`response_format=json_object`), резюме/требования/риски формируются по тексту документации.

## API

- `GET /api/tenders` — тендеры из хранилища. Параметры: `date_from`, `date_to` (YYYY-MM-DD, по дате размещения), `query` (поиск по названию), `domain`, `limit`.
- `POST /api/upload` — разовый анализ загруженного файла (поле `file`), API-only, не зависит от пайплайна.
- `GET /api/requirements` — словари доменов и критерии анализа.
- `GET /api/health` — проверка сервера.

## Ограничения прототипа

- Скачивание вложений зависит от структуры страниц ЕИС (изолировано в `fetch_attachments`, не роняет прогон).
- Старый бинарный формат `.doc` не извлекается (только `.docx`); OCR для PDF без текстового слоя — следующий этап.
- Заголовок тендера иногда не распознаётся парсером листинга — тогда поиск по названию по такой карточке не сработает.
- Производственный контур: вынести словари в админку, добавить аудит, ретраи и инкрементальное обновление статусов.
